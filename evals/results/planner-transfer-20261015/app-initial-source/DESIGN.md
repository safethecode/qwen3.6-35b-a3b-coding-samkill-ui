# Personal weekly task planner

Mobile-only new service scenario. Users choose a day, create study/life tasks, mark them complete and remove them. White background follows the updated upstream default. The source reference supports week/category grouping; social profiles, ads and AI recommendation features are outside this product. No existing workshop photo/price/booking layout is relabeled as this service. Host supplies markup/shared layout and licensed font/officialicons. All initial/generated inputs are frozen before local generation.

Behavior remains NOT IMPLEMENTED after static generation. A subsequent local-model behavior stage must derive the current local week, render seven day buttons, store selected tasks under weekly-tasks-v1 with validated task IDs/title/category/date/boolean completion, use textContent and the template for user text, and support create/toggle/delete, date filtering, reload, empty state and storage-error recovery. No sample records are seeded. A write failure must preserve visible data and form contents. Empty titles and malformed stored dates/records are invalid. Dialog close/Escape returns focus to the actual opener.

Required checks: four viewport widths, long Korean titles, 200%text/spacing, final week-day access within its own scroller, create in both categories, complete/reload, remove/reload, day switch isolation, blank-title rejection, safe HTML-like text, malformed storage, read/write/remove errors and focus/forced-colors. Static CSS output is not a completed application or quality parity.
