# Complex mobile stay booking: research and scope

The user rejected the timer as too simple for the primary quality comparison. This study now targets connected accommodation discovery,filters and date/guest selection,property detail and room/rate comparison,price review,local booking requests,and later change/cancellation. The earlier timer remains an incomplete separate dependency study;its results do not establish quality for this product.

The [original brief](inputs/BRIEF.md) was fixed before the new research. Eight UI Bowl calls returned18native representative previews,which were directly inspected and preserved locally. The [source index](reference-index.json) records image hashes,retrieval times,canonical UI URLs and returned screen IDs where available. The first unsupported filter-component query returned zero;one retry using the supported slider component found the actual filter screen. There was no extra pagination. [Sanitized receipts](receipts) preserve both calls and all other branches.

[Decomposition](inputs/DECOMPOSITION.md) separates discovery,detail,review/request and management references. The first core comparison uses Airbnb's photo-led result hierarchy;the reservation review separates editable trip facts,fees and total. Dailyhotel contributes policy-before-cancellation hierarchy;MyRealTrip contributes cancelled-state identity and date grouping. Promotional landing content,community-post deletion,unverified reviews/host portraits and card-payment entry are excluded for explicit reasons. The [earlier decomposition](inputs/DECOMPOSITION-v1.md) preserves a generic4:3photo choice;the prospective first-style input corrects it to nearly square based on the actual inspected result image.

UI Bowl is the reference database. Host planning,markup,shared runtime,assets and typed fixtures are disclosed assistance. Local Qwen supplies bounded business/controller/CSS units;raw failures and repairs remain separate. This is a new product adaptation,not blind reproduction or unattended all-Qwen generation.

The product uses fictional local catalog fixtures. It does not charge cards,book external hotels,confirm vendor inventory or issue refunds. No claim of commercial/reference parity follows from this research,source files or passing dependency tests. [The complete plan](inputs/PLAN.md) still requires connected request creation/change/cancel flows,custom calendar behavior,actual typography/icons,all active75rules/eight guides and repeated rendered comparisons. Public source URLs and image hashes do not substitute for inspecting the actual reference pixels.
