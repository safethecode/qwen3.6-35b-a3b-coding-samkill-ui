# Semantic reference component generation

This experimental route translates a previously inspected reference decomposition into static element samples and an assembled page. It does not implement product workflows or certify commercial quality. The existing service route still handles those workflows separately.

Text-stress inspection waits for loaded fonts and two consecutive unchanged geometry frames before measurement/capture,with a12frame budget. `layoutSettlement` stays `UNVERIFIED` when that budget expires and needs fresh evidence;the service evaluator keeps this as a required review finding. Stable geometry is not visual/paint or asynchronous-network completion. Keep a prematurely cropped screenshot as failed evidence rather than resizing it or silently inheriting its review.

Layout rules optionally accept a nonempty unique `modes` array, alongside `states` and `widths`. For example, a native date-pair `sameRow` can be mandatory for `modes:["normal"]`, while whole-token readability remains mandatory in normal, enlarged and spacing captures. Declare this distinction before repair; mode scope is not permission to remove a failed requirement. The inspector selects the actual `options.mode` (default `normal`); the coverage aggregator still requires every requested capture and every rule's declared mode, including modes outside a narrower requested matrix. Missing/invalid scopes remain unverified and any failed observation in the batch remains failed.

Create a fresh target containing `DESIGN.md`, `REFERENCE.md`, official local assets, `design/typography.json` and `design/component-plan.json`. Prepare local fonts as described in [quality verification](QUALITY.md). The plan has:

- `reference`: inspected source, original observation region, comparison width, provenance and unknowns.
- `shared`: common visual relationships and chosen implementation constraints.
- `sharedCss`: explicitly host-supplied tokens, frame/card wrappers and typography.
- `elements`: IDs, focused prompts, allowed asset paths and standalone sample templates.
- `assembly`: a template with each `{{elementId}}` exactly once. Each sample includes only its own slot and reproduces its assembly slot's available width and parent padding.

An element can supply immutable `html` when its semantic structure and copy are already decided. That request returns CSS only; the model cannot insert an unrelated profile, action or image into the fixed fragment. `fixedMarkupElements` lists this host assistance in the generation record. This is useful for small bodies, labelled fields and footers; it is not evidence that the model independently discovered their structure.

Each model call writes one root with `data-ui-unit="elementId"` and CSS scoped to that root. Its prompt receives the shared contract and only that element's requirements. The runner scopes local class/type selectors to the component root; document selectors and sibling escapes are rejected. Scripts, inline handlers/styles and undeclared media are rejected. Accepted HTML/CSS is reused unchanged for its sample and assembly; the model never rewrites the completed page during assembly.

Run `node scripts/generate-components.mjs TARGET EVIDENCE`, with evidence outside the source directory. Use the normal local model environment variables. Each element has two bounded attempts and a five-minute request timeout. Raw responses, errors and input-bound checkpoints are retained. Set `QWEN_RESUME=1` to resume only unchanged inputs and runner state after an interrupted element; completed elements are validated and reused. Completed application source cannot be overwritten.

Outputs include `index.html`, `styles.css`, a static `app.js` and `sample-ID.html` per element. The report explicitly records shared CSS, font loading, selector scoping and assembly as host assistance. Rejected code and its validation error are supplied together on the bounded retry. No automatic typography normalization is applied to model CSS in this route. Browser checks and direct source/render comparison are still required. Scoped CSS is not proof of geometry, responsive behavior, complete visible labels or correct asset states.

Reuse the upstream reference-decompose E/O records and corrected prompts. Keep observed values distinct from chosen CSS values and product adaptations. Compare the actual element and whole-page renders at the same available width, then verify all relevant original guide/catalog requirements. Do not replace the reference-quality requirement with a component pass count.

## Repair one existing element

Component generation receives the actual local decomposition, upstream typography, design-guardrail and mobile guide text. Components with declared SVG assets also receive the icon-control guide. Per-element guide paths and SHA-256 hashes are recorded in generation inputs and bound to checkpoints. These focused styling guides do not replace the full 75-rule/eight-guide completion review or interaction verification. Their presence in a request is not evidence that the output obeys them.

The component validator rejects all `+` and `~` selector combinators, including descendant siblings within a valid component root. Use a parent gap or `:not(:first-child)` for repeated-group spacing. Generation prompts state this restriction explicitly, and retry errors identify the rejected selector. This restriction has not been loosened for a particular reference.

Run `node scripts/repair-component.mjs TARGET EVIDENCE ID COMPONENT_JSON FAILURE_TEXT` with a fresh evidence directory outside the source. COMPONENT_JSON contains the exact current `{html, css}` fragment; FAILURE_TEXT describes the observed defect and relevant reference comparison. Use the `after` fragment from the latest accepted repair when repairing an element again. Never reuse stale generation fragments after changing that element.

The runner checks that the fragment occurs exactly once in both assembly and sample and that its CSS matches the current stylesheet. It supplies shared and element contracts to the local model and accepts at most three bounded patches. Fixed plan HTML stays immutable. Undeclared assets, escaping CSS, truncated output and source/harness changes are rejected before writes. The same accepted HTML is applied to sample and assembly, and unrelated elements and behavior remain untouched. Raw responses and before/after bindings are saved.

This is a reusable repair primitive, not an automatic visual defect selector or approval loop. Run browser checks and direct reference comparison after every repair. Preserve failed candidates as evidence. The caller must serialize inference and decide which element and defect require repair; a successful application reports APPLIED_NOT_APPROVED.

Repair requests also receive the complete applicable decomposition, typography, guardrail, mobile and spacing guides; SVG-bearing components receive icon guidance too. The request record retains their source hashes. This is the same guide routing as generation, not proof of compliance. Keep diagnosis and the writable region bounded even when the applicable guides are supplied.

## Prescribed computed CSS roles

For a property already fixed by the design contract, a layout rule may use `kind: "computedStyle"`, one visible `subject` selector and a `properties` object of canonical browser-computed strings, such as `{ "border-radius": "24px", "flex-wrap": "wrap" }`. Choose the expectations before generation or repair and scope them by the existing `states` and `widths` fields when needed. The inspector rejects unsupported property/value pairs and mismatched computed values after inheritance, custom-property resolution and the cascade. It requires exactly one visible subject; an absent or ambiguous selector cannot pass. Values such as colors must use their canonical computed serialization. These checks supplement geometry, stress and direct reference review; they do not approve appearance or diagnose whether a mismatch comes from the host contract, native control or model.

A contract supports 1–128 uniquely identified rules. This bounded capacity allows a connected product to retain earlier checks while adding relationships for later consumers. Every applicable rule is inspected, including rules after the former 64-rule limit; none are truncated. State/mode coverage, failures, unknowns and selector validation remain unchanged. The rule-count limit is a resource bound, not a visual quality threshold.

Whole dates, short labels and numeric units can fragment without producing horizontal overflow. Declare their actual uniform text owner and semantic group before repair with `kind: "readableToken"`. For example, `{ "id": "check-in-date", "kind": "readableToken", "subject": "#review-start", "container": ".booking-dates", "token": "whole", "states": ["booking"] }` checks the complete displayed date. `{ "id": "total-unit", "kind": "readableToken", "subject": "#review-total", "container": ".booking-pricing", "token": "number", "suffix": "원", "states": ["booking"] }` follows the actual dynamic number and literal unit. Do not use an arbitrary large ancestor to excuse a narrow child, or a narrower owner to turn a known fragmentation failure into unknown. Owner choice follows content responsibility; the inspector measures its current content width.

The rule requires exactly one visible subject, one containing owner and one uniform owned text node. The complete token must fit one rendered line when its measured intrinsic width fits the semantic group. Numeric selection requires one complete whitespace-bounded numeric token; an optional suffix is a literal unit of at most32characters, not a regular expression. Interrupted amounts, embedded formatting controls and partial trailing-number matches fail. Missing/ambiguous text, actual overflow clipping, transparent text paint, subject overflow, transformed/scaled text and unsupported ownership fail. Unsupported painted clips, filters, masks, rotations, generated content or pseudo typography stay `UNVERIFIED`. A token intrinsically wider than its semantic owner also stays `UNVERIFIED` and needs explicit layout/content review; it never passes automatically. Enlarged text may reflow its component while keeping a whole token readable. This gate supplements normal-layout relationships such as `sameRow`; preserving words alone cannot approve reference structure, actual date/price meaning, mixed typography, contrast, device zoom or visual quality.

## Actual data at element boundaries

An element can declare up to four `dataSources`, each with exactly `id`, `file` and `pointer`. For example, `[{"id":"room","file":"catalog.json","pointer":"/0/rooms/0"}]` delivers only that actual JSON record. The JSON pointer follows `~1` for a literal slash and `~0` for a literal tilde; an empty pointer selects the JSON root. Use small records containing the actual identity and owned fields required by the element. A quote's `rateId` and a catalogue rate's `id` are different keys; the supplied data preserves them instead of guessing a schema from a display label.

Files stay inside the project and cannot use symlinks. Missing pointers, invalid JSON, duplicate source IDs or a combined selected payload over12000characters fail before inference; values are never silently truncated. `inputs.json` records the whole-file SHA256 and delivered-value SHA256 per element. Data sources participate in checkpoint identity and are reread before assembly, including JSON files under `design/` that are outside the ordinary source inventory. A changed source rejects generation without replacing the user's changed data.

The exported `readElementDataContext(target, element)` in `scripts/element-data.mjs` also supports bounded behavior callers. Its `text` is read-only data for the prompt and `sources` is the binding receipt. This supplies actual values; it does not implement behavior, resolve contradictory prose or establish generation/visual quality. The room study in `evals/results/stay-booking-20261016/room-evidence` preserves the concrete missing-field and host-input failures that motivated this interface.

## Long-running local inference

Generation and component repair use a Node HTTP/HTTPS transport with an explicit total deadline instead of the implicit fetch response-header timeout. The default deadline is 600,000 milliseconds. Set `QWEN_REQUEST_TIMEOUT_MS` to an integer between 1,000 and 1,800,000 to override it. Existing smaller per-unit repair deadlines remain the default for the general repair runner. Component generation records its deadline in the input binding; changing it invalidates checkpoint reuse. Requests remain bounded and truncated model output is still rejected. A transport fix does not establish visual quality or guarantee that a model finishes within the chosen deadline.
