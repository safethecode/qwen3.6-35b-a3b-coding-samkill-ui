## Prescribed computed CSS roles

For a property already fixed by the design contract, a layout rule may use `kind: "computedStyle"`, one visible `subject` selector and a `properties` object of canonical browser-computed strings, such as `{ "border-radius": "24px", "flex-wrap": "wrap" }`. Choose the expectations before generation or repair and scope them by the existing `states` and `widths` fields when needed. The inspector rejects unsupported property/value pairs and mismatched computed values after inheritance, custom-property resolution and the cascade. It requires exactly one visible subject; an absent or ambiguous selector cannot pass. Values such as colors must use their canonical computed serialization. These checks supplement geometry, stress and direct reference review; they do not approve appearance or diagnose whether a mismatch comes from the host contract, native control or model.

Exact metrics can faithfully enforce a wrongly chosen heading role. Before assigning numbers, record the observed size/weight relationship between the task heading and relevant neighboring content. `typeRelation` checks that declared relationship between two distinct, single visible DOM text owners. Require positive finite ordered `minSizeRatio`/`maxSizeRatio` bounds; optional `minWeightDifference`/`maxWeightDifference` bounds must be supplied together and ordered within-999–999. The ratio is subject size divided by reference size; the difference is subject weight minus reference weight. This example encodes equal emphasis for an observation that supports it; it is not a universal heading recipe:

```json
{"id":"task-card-role","kind":"typeRelation","subject":"#task","reference":"#card","minSizeRatio":1,"maxSizeRatio":1,"minWeightDifference":0,"maxWeightDifference":0}
```

The inspector records actual computed CSS metrics and checks nonempty uniform owned text. Missing, ambiguous, hidden, identical or ancestor/descendant overlapping owners and invalid bounds fail. Mixed descendant metrics, generated content, first-letter/first-line pseudo typography and transformed/zoomed text, including individual CSS scale/rotate, stay `UNVERIFIED`; they never pass from the parent's numbers alone. Uniform text enlargement preserves a ratio, while enlarging only one role can fail it. These are CSS size/weight relationships, not painted glyph-size, optical-weight, font identity, contrast or complete appearance checks. Keep exact-role/font/stress inspections and direct native comparison. Correct a contradictory host role before another local request and preserve the old input; do not infer the relationship from a successful output or change a contract merely to clear its failures.

A contract supports 1–128 uniquely identified rules. This bounded capacity allows a connected product to retain earlier checks while adding relationships for later consumers. Every applicable rule is inspected, including rules after the former 64-rule limit; none are truncated. State/mode coverage, failures, unknowns and selector validation remain unchanged. The rule-count limit is a resource bound, not a visual quality threshold.

Whole dates, short labels and numeric units can fragment without producing horizontal overflow. Declare their actual uniform text owner and semantic group before repair with `kind: "readableToken"`. For example, `{ "id": "check-in-date", "kind": "readableToken", "subject": "#review-start", "container": ".booking-dates", "token": "whole", "states": ["booking"] }` checks the complete displayed date. `{ "id": "total-unit", "kind": "readableToken", "subject": "#review-total", "container": ".booking-pricing", "token": "number", "suffix": "원", "states": ["booking"] }` follows the actual dynamic number and literal unit. Do not use an arbitrary large ancestor to excuse a narrow child, or a narrower owner to turn a known fragmentation failure into unknown. Owner choice follows content responsibility; the inspector measures its current content width.

The rule requires exactly one visible subject, one containing owner and one uniform owned text node. The complete token must fit one rendered line when its measured intrinsic width fits the semantic group. Numeric selection requires one complete whitespace-bounded numeric token; an optional suffix is a literal unit of at most32characters, not a regular expression. Interrupted amounts, embedded formatting controls and partial trailing-number matches fail. Missing/ambiguous text, actual overflow clipping, transparent text paint, subject overflow, transformed/scaled text and unsupported ownership fail. Unsupported painted clips, filters, masks, rotations, generated content or pseudo typography stay `UNVERIFIED`. A token intrinsically wider than its semantic owner also stays `UNVERIFIED` and needs explicit layout/content review; it never passes automatically. Enlarged text may reflow its component while keeping a whole token readable. This gate supplements normal-layout relationships such as `sameRow`; preserving words alone cannot approve reference structure, actual date/price meaning, mixed typography, contrast, device zoom or visual quality.

For repeated plain text owners, `textGap` measures separation between text ranges rather than control boxes. Declare a unique `subject`,relative `groups` and `text` selectors,`axis: "inline"` or `"block"`,and a finite nonnegative `minimum` in CSS px. Example: `{ "id":"calendar-date-spacing","kind":"textGap","subject":"#date-calendar","groups":"#calendar-months tbody tr","text":".calendar-day","axis":"inline","minimum":8 }`. The8px minimum is this calendar's chosen value,not a shared default. A block-axis rule can group a tbody and compare its same-column text ranges.

The inspector compares pairs sharing a cross-axis band,including RTL physical order,and records every measured pair and the minimum with0.05px rounding tolerance. A glyph can fit its cell while the adjacent text gap still fails. Missing pairs,hidden/empty/mixed or fragmented owners,vertical writing,transforms/zoom,generated content on owners or their ancestors,overlapping group ownership and bounded measurement limits remain UNVERIFIED;invalid contracts fail. There are limits of128groups,128owners pergroup,512totalowners and16,384pairs. These are layout text ranges,including offscreen layout,not raster ink,clipping,scroll reachability,font identity,contrast or reference-quality approval. Keep separate whole-token,containment,actual scroll/focus and direct visual checks.

For a predeclared solid monochrome icon or plain text role on an opaque white surface, `monochromePaint` inspects actual browser PNG pixels. The expected `foreground` is a six-digit hex color fixed from the design/state contract before generation; do not copy the candidate's computed color into the expectation. Use `paintMode: "icon"` for one SVG/image slot or `paintMode: "text"` for one nonempty plain HTML text owner without child elements or pictographic glyphs. For example:

```json
{"id":"selected-icon-paint","kind":"monochromePaint","subject":"#icon","paintMode":"icon","foreground":"#b51d51","states":["selected"]}
```

The inspector catches external SVG images that paint black even when their CSS `color` matches a selected label. Icon pixels must follow the expected foreground-to-white alpha-compositing ray. Text allows independent per-channel antialiasing and requires at least five actual expected-color core pixels; using the icon ray for Windows subpixel text can falsely reject correct labels. A second clip with the owner's opacity temporarily zero must expose only opaque white; the exact original inline style is restored. This leaves overlapping or underlying foreign paint unresolved rather than crediting it to a transparent icon. Unsupported backgrounds, images behind the subject, effects, transformed opacity, text strokes, animations/transitions, mixed text owners, generated/pseudo text and sparse foreground evidence remain `UNVERIFIED`. Foregrounds within 29 levels of white and clips smaller than one CSS pixel are below the measurement threshold and stay unknown. Wrong painted colors or suppressed icon/transparent text paint fail. A six-digit color alone does not establish contrast or applicability. Multicolor branding, colored fonts, gradients, devices and forced-color modes need their own review.

The entire owner must fit inside the viewport after scrolling; a clipped portion cannot approve an oversized/offscreen owner. Active Web Animations API effects on the owner, ancestors or descendants also remain unknown, even when CSS animation declarations are unset. The existing width/state/mode scoping and `aggregateLayoutStates` coverage apply. Inspect every required selected and unselected state, real text enlargement and spacing; declaring a state does not activate it. PNG hashes and decoder identity identify the measured clip, not the complete source or reference. Keep source/harness bindings, official geometry/provenance, typography, target/edge/focus tests and direct visual review. A paint pass does not prove complete shapes, unobscured content, optical alignment or reference parity.
