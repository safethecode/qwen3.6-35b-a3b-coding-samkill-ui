# Primary 컬러를 선택하고 화면에서 확인하기

새 Primary 색을 고르거나 기존 색의 적합성·위계에 대한 교정을 받았을 때 읽는다. 사용자가 지정한 브랜드·정확한 재현 범위를 우선한다. 특정 색상이나 채도를 모든 제품의 기본값으로 만들지 않는다.

## 기본 배경은 흰색

사용자의 공통 요구에 따라 디자인의 기본 화면 배경은 순백색 `#FFFFFF`로 고정한다. 오프화이트·크림·연회색·브랜드 틴트로 대체하지 않는다. 다크모드는 사용자가 명시적으로 요청한 경우에만 적용한다. 어두운 레퍼런스·기존 데모·기기 설정·업종·사진 분위기는 다크모드 요청이 아니다. 정확한 재현 요청에서도 원본 관찰을 보존하고 이 배경 요구에 따른 적용 차이를 기록한다.

기본 화면 배경과 버튼·입력·선택·상태·사진 같은 내부 요소의 역할을 구별한다. 내부 표면의 색은 필요한 기능 범위에서 결정하며 화면·섹션의 바탕 전체를 틴트나 어두운 면으로 덮어 기본 배경을 우회하지 않는다. Primary와 보조/강조색은 흰 바탕에서 조합한다. 다크모드를 명시적으로 요청하면 해당 테마의 배경·전경·상태를 함께 설계한다.

## 먼저 고정된 것과 선택할 것을 구별하기

기존 브랜드색·토큰·실제 사용처와 현재 사용자 요구를 확인한다. 승인된 색은 유지하며 역할·전경·표면·사용 면적에서 문제가 생겼는지 먼저 진단한다. 기존 라이브러리 기본색이나 이전 데모 색은 브랜드 근거가 아니다. 새 제품이면 핵심 과제, 실제 내용/사진, 사용 환경, 확인한 레퍼런스의 색 관계를 선택 근거로 삼는다. 업종만 보고 ‘금융은 파랑’, ‘건강은 초록’처럼 색을 자동 배정하지 않는다.

Primary가 뜻하는 역할을 명시한다. 브랜드를 식별하는 색, 핵심 행동의 배경, 선택 상태, 정보 링크, 성공/위험 상태는 사용 목적이 다르다. 같은 값으로 시작해도 변경 책임이 다르면 의미 토큰을 나눈다. 제품의 주 행동에 검정·흰색 등 무채색이 적합하면 유효한 선택이며, Primary 필드를 채우려고 유채색을 추가하지 않는다.

## 브랜드의 인상과 차별화를 후보에 연결하기

사용자가 제공한 브랜드 가치·이미지와 대상 사용자의 상황을 색 선택 입력으로 사용한다. 색의 연상 의미는 후보를 만드는 가설이며 모든 문화·제품의 공통 반응이나 업종별 정답이 아니다. 형용사만 남기지 말고 실제 화면과 연결한다.

| 전달할 인상에 따른 후보 | 확인할 관계 |
|---|---|
| 신뢰·안정·전문성의 파랑, 중립·균형의 회색 | 실제 톤과 주변 표면이 그 인상에 맞는지, 경쟁 서비스와 구별되는지 |
| 에너지·열정의 빨강, 활력·친근함의 주황 | 위험/오류 신호와의 의미 충돌, 콘텐츠와 행동의 강조 경쟁 |
| 자연·성장·건강의 초록 | 사진·콘텐츠의 초록에 조작이 묻히는지, 성공 상태와 역할이 구별되는지 |
| 밝음·창의성의 노랑, 창의·신비의 보라 | 흰 배경과 전경의 대비, 채도가 넓은 영역에서 과도해지는지 |
| 부드러움·로맨틱함의 분홍, 세련됨의 검정, 청결·단순함의 흰색 | 대상과 표현의 적합성, 글자/주 행동/표면 위계. 사용자 성별로 자동 배정하지 않기 |

시장/경쟁 자료가 이미 있으면 실제 화면의 주요 색·톤·면적·조합을 비교한다. 브랜드 차별화가 과제이고 자료가 부족하면 해당 범위만 추가 조사한다. 같은 색상 계열도 톤·조합·사용 역할로 차별화할 수 있으므로 색상 하나의 중복만으로 후보를 폐기하지 않는다. 조사를 실행하지 않았으면 경쟁 분석 완료라고 기록하지 않는다.

## Primary와 함께 팔레트를 구성하기

색 하나를 고른 다음 나머지를 즉흥적으로 추가하지 않고 아래 역할을 함께 정한다. 역할 개수와 서로 다른 HEX 개수는 같을 필요가 없다.

| 팔레트 역할 | 결정할 내용 |
|---|---|
| 기본색 | 화면 바탕 `#FFFFFF`, 본문/보조 글자와 필요한 내부 표면. 브랜드 틴트로 기본 배경을 바꾸지 않기 |
| 주요색 | 브랜드의 인상·식별을 맡을 색. 반복할 위치와 의미 토큰 |
| 보조색 | 주요색을 보완하거나 관련된 정보/기능을 구별하는 색. 실제 구별할 대상이 있을 때 추가 |
| 강조색 | 핵심 CTA·중요 정보의 주의를 맡을 색과 전경. 주요색이 이 역할도 맡을 수 있으며 별도 보색은 필수가 아님 |

[UI를 위한 색](https://brunch.co.kr/@blckschrl/41)의 배색 접근을 활용해 단색은 톤의 통일, 유사색은 관련 항목의 구별, 보색은 강한 강조 후보로 검토한다. 어느 조합이든 실제 기능·위계를 먼저 정하고 흰 바탕의 전경/표면과 함께 확인한다. 색상환 각도만 맞춘 것을 조화·가독성 통과로 보지 않는다.

사용자가 제공한 60-30-10은 기본·주요·강조 영역의 초기 비중을 구상할 때 활용한다. 링크 글의 사례는 흑백 바탕과 포인트 면적을 비교하며 비율을 달리한 화면도 보여준다. 따라서 브랜드색이 30%를 반드시 차지하도록 화면을 칠하지 않는다. 사진 중심이면 흰 바탕과 콘텐츠를 넓게 두고 주요색이 작은 CTA/강조 역할을 맡는 구성을 시험한다. 비중을 수치로 기록하면 사진·글자·여백 중 무엇을 포함했고 추정인지 측정인지도 남긴다.

필요한 밝고 어두운 변형은 명도뿐 아니라 채도·색조도 조정 후보로 검토한다. 링크 글의 변형 예시는 비교 출발점이며 모든 색의 변환 공식이 아니다. 실제 상태별 색쌍과 일관성을 검사한다. 웹/앱용 HEX·RGB와 역할·상태를 관리하고, 인쇄가 요청되면 해당 매체에서 확인한 CMYK/Pantone 등 사양을 별도로 연결한다. 매체 검증 없이 색 코드의 동일 외관을 보장하지 않는다.

## 색 이름보다 실제 관계로 후보 만들기

주 레퍼런스에서 강조색의 색상 계열·명도·채도, 뒤 표면의 밝기/색 기운, 글자/아이콘의 전경색, 강조색이 차지하는 영역과 반복 위치를 관찰한다. 사진과 조작의 색이 어떻게 구별되는지도 남긴다. 사진에서 많이 보이는 색을 그대로 CTA에 쓰면 조작이 묻힐 수 있다. 이미지 샘플과 원본 CSS 값은 구별한다.

새 선택에는 `제품 요구/내용 | R/O/Q 근거 | 유지할 색 관계 | 후보 값·전경·표면 | 채택/배제 이유 | 실제 비교`를 연결한다. ‘차분함’, ‘프리미엄’, ‘신뢰감’ 같은 형용사만으로 결정을 끝내지 않는다. 예를 들어 사진의 강한 따뜻한 색과 다른 계열로 조작을 구별할지, 흰 바탕에서 작은 주 행동 면적을 얼마나 선명하게 드러낼지처럼 화면에서 대조할 관계를 적는다. 이런 효과는 설계 가설이며 사용자 반응의 검증된 사실로 쓰지 않는다.

익숙한 파랑·보라, 회색이 섞인 저채도 포인트색, 모든 표면의 옅은 브랜드 틴트를 관성적으로 채택하지 않는다. 동시에 이 색들을 금지하거나 모든 제품에 강한 원색을 요구하지 않는다. 낮은 채도가 맞는 화면도 주요 행동이 주변 표면과 식별되고 제품/레퍼런스의 표현이 살아 있는지 확인한다. 명도·채도·면적을 함께 보고 강한 색이 필요한 역할에 충분한 강조를 남긴다. 예시 문서의 HEX는 후보 근거가 아니다.

## 결정이 갈리면 같은 화면에서 비교하기

색 선택을 새로 해야 하고 근거만으로 판단이 갈리면 비교할 축을 정해 대안을 핵심 화면에 적용한다. 색상 계열, 명도/채도, 표면 조합, 사용 면적 중 판단이 필요한 축을 구별한다. 문구·사진·레이아웃·뷰포트는 같게 두고 필요에 따라 색과 연동되는 전경/표면을 함께 조정하되 바뀐 역할을 기록한다. 색칩만 비교하거나 후보마다 배치를 바꿔 원인을 흐리지 않는다. 후보 개수·배색 비율·사용자 선택 절차를 고정하지 않는다. 구현을 위임받았다면 근거로 결정하고 계속한다.

실제 화면에서 다음을 확인한다.

- 첫 시선과 핵심 행동: Primary CTA가 보조 버튼·선택·배지와 구별되는가? 강조할 행동의 범위와 위치도 적합한가?
- 내용과 표면: 사진·데이터·본문을 압도하거나 그 색에 묻히지 않는가? 중립 표면의 색 기운과 강조색이 의도한 조합을 이루는가?
- 사용 면적과 반복: 모든 제목·아이콘·카드·배지를 같은 Primary로 칠해 강조가 분산되지 않는가? 흰 기본 배경이 유지되는가? 필요한 내부 컬러 요소에서도 행동 위계를 확인하며, 비율을 맞추려고 넓은 컬러 바탕을 추가하지 않는다.
- 상태와 접근성: 기본·hover·pressed·loading·선택·focus에서 전경과 조작 신호가 유지되는가? 성공/위험과 의미가 혼동되지 않는가? 색 외에 필요한 라벨·형태·초점 신호가 남아 있는가?

대비는 [토큰 계약](design-tokens.md#합성-배경과-대비-근거)의 실제 전경/합성 배경과 적용 기준으로 검사한다. 흰 글자를 자동 선택하거나 Primary 자체를 낮은 opacity로 만들어 disabled·hover를 대충 생성하지 않는다. 다른 전경·역할별 명도·배경·사용 면적 중 적합한 조정을 선택하고 관련 사용처를 다시 확인한다. 대비 수치 통과는 제품에 어울리는 색이나 좋은 위계의 증거를 대신하지 않는다.

## 결정과 재검증을 보존하기

선택한 색쌍·상태·사용 범위를 대상 DESIGN.md와 토큰에 연결한다. 레퍼런스의 관찰색과 새 chosen 값을 구별하고 같은 값의 다른 역할을 전수 대조한다. 공유 Primary를 바꾸면 버튼뿐 아니라 링크·선택·포커스·상태·인접 표면 등 실제 소비 영역을 확인한다. 모든 역할을 새 색으로 일괄 치환하지 않는다.

사용자가 ‘안 어울린다’, ‘탁하다’, ‘강조가 안 보인다’고 교정하면 색상 계열·명도·채도·표면·면적·행동 위계 중 어떤 관계가 어긋났는지 원본과 현재 화면으로 확인한다. 장식색 추가나 채도 일괄 상승으로 덮지 말고 필요한 역할을 수정·재렌더한다. 최초 선택과 교정을 보존한다. 특정 화면이 제공되지 않았으면 가능한 원인과 보완 기준을 기록하며 그 제품의 색 실패나 해결을 확정하지 않는다.

명세 전용에서는 선택 근거·역할·색쌍·실제 비교 계획을 전달한다. 실제 렌더를 확인하지 않은 적합성·위계·상태 검증은 미검증으로 남긴다.
