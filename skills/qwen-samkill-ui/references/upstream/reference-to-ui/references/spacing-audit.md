# Spacing Audit — 4/8단위 간격 점검

간격을 설계·수정하거나 리듬의 일관성을 검토할 때 적용한다. 새 디자인은 구조 간격을8단위, 촘촘한 컴포넌트 내부를4단위 중심으로 정한다. 기존 시스템은 먼저 확인하고 보존한다. 숫자를 맞추는 것으로 요소 관계·밀도·사용성 검증을 대신하지 않는다.

## 스케일과 판정

기본 목록: `0, 4, 8, 12, 16, 24, 32, 40, 48, 56, 64, 80, 96`.
사용자 원문의 내부 간격 항목에 따로 명시된 **20은 컴포넌트 내부의 허용값**으로 포함한다. 새 값을 임의로 추가하지 않는다.

| 역할/값 | 기준과 처리 |
|---|---|
| 구조 간격 | 섹션/그룹 사이, 카드 바깥 레이아웃, 콘텐츠 여백과 넉넉한 카드 패딩은 목록의8배수에서 선택한다. 0은 간격이 필요 없는 관계에만 쓴다. |
| 촘촘한 내부 간격 | 칩 패딩·짧은 스택 등은4/8/12/20을 포함한 목록에서 실제 관계에 맞게 고른다. 카드 안이라고 모든 패딩을 작은 값으로 압축하지 않는다. |
| 아이콘–라벨 간격 | 새 결정·수정 후보는4 또는8. 더 큰 값으로 반올림하지 않는다. 기존 토큰·의도된 예외는 아래 보존 기준을 따른다. |
| 4의 배수가 아닌 고정 간격 | 보존 대상이 아니면 `off-grid`로 보고하고 가장 가까운 해당 역할의 허용값을 제안한다. 예: 카드 패딩14→16. |
| 구조의4배수이면서8배수가 아닌 값 | 12/20/28 등은 `8pt step 검토` 의견이다. 이 이유만으로 하드 오류/제품 FAIL로 바꾸지 않는다. |
| 목록 밖의4배수 | 28/72/88 등은 `스케일 정렬 검토`로 보고하고 목록 안의 후보를 제안한다. 4배수라는 이유로 새 허용값에 추가하거나 하드 오류로 바꾸지 않는다. 구조28은 위 의견도 함께 표시한다. |

간격 단위를 명시한다. 웹은 CSS px, 디자인 도구는 해당 문서 단위로 검사하며 이를 인쇄용 pt로 변환하지 않는다. image-px나 스크린샷 추정값을 정확한 CSS/디자인 값으로 확정하지 않는다. rem은 실제 기준값과 환산 근거를 함께 기록한다.

## 범위와 보존 대상

선택 프레임이 있으면 그 하위, 없으면 대상 페이지 전체를 위에서 아래로 조사한다. 코드에서는 대응하는 화면/컨테이너를 정한다. 사방 padding, 자식 gap/item spacing, 섹션·그룹 사이 거리, 프레임 안 콘텐츠 margin을 확인한다. 같은 요소의 중복 방문을 제거하고 요소 수와 간격값 수를 따로 센다. 반응형·상태별 값은 대상 폭/상태와 함께 남긴다. 접근하지 못한 프레임은 누락과 이유를 보고하며 전체를 검사했다고 하지 않는다.

다음은 off-grid 목록에서 제외하고 **보존값/이유**로 기록한다.

- 변수·토큰에 연결된 간격: 이름, 정의/별칭, 최종 값, 소비 위치를 남기고 연결과 값을 그대로 둔다. 사용처를 직접값으로 치환하거나 토큰 원본을 반올림하지 않는다. 토큰값18도 이 감사에서는 보존한다. 새 임의값에 토큰 이름을 붙여 검사를 회피하지 않는다.
- 1px 테두리/hairline: 간격과 구별한다. 간격 감사에서 수정하지 않으며, 금지된 영역 구분선이 발견되면 기존 규칙으로 별도 기록한다.
- 의도된 광학 정렬 보정: 기존 계약/원본과 실제 정렬 근거를 남긴다. 임의값을 사후에 ‘광학 보정’으로 정당화하지 않는다.
- hug/fill, auto, 비율, flex/grid 분배 등 내용·가용 공간으로 결정되는 거리와 safe area: 계산 방식·원인을 남긴다. 렌더된 소수점 거리를 고정 px로 바꾸지 않는다.

한 그룹이 의도적으로6단위 체계를 쓰는 등 균일한 별도 시스템이면 **그룹 단위로 한 번 보고하고 보존**한다. 4/8단위로 일괄 전환하라는 권한이 아직 없으면 전환 전에 사용자에게 확인한다. 이미 명시적으로 승인된 전환은 다시 묻지 않는다. 일반적인 off-grid 수정마다 승인을 요구하지 않는다.

토큰 보존은 실제 레이아웃 결함의 면제가 아니다. [패딩 소유권](design-tokens.md#공통-화면-컨테이너의-패딩-소유권)과 [부모·자식 여백 합](ui-composition.md#부모자식과-상태별-여백의-합-확인)을 별도로 확인한다. 토큰끼리 합쳐진 이중 여백·잘림·가림은 RUI-22 등 기존 실패로 남긴다. ORC-F12/G07/G20과 충돌하는 보존값은 해당 규칙 ID·범위·사용자 제약·실제 근거/검증을 프로젝트 예외 절차에 연결한다. 이 참고 문서는 catalog를 해제하거나 새로운 게이트 자동 PASS를 만들지 않는다.

## 조사 → 요약 → 수정

1. 값의 출처/단위·바인딩·역할을 확인하고 보존 대상부터 분리한다. 정확한 값을 읽을 수 없으면 `미확인`으로 두고 수정하지 않는다.
2. 나머지를 분류하고 가장 가까운 허용 후보를 고른다. 중간값이면 주변 그룹의 지배적인 리듬으로 결정한다. 같은 역할의 카드가14/16/16이면14→16으로 맞추고 두16은 유지한다. 다른 의미 그룹까지 같은 gap으로 통일하지 않는다. 아이콘–라벨6은 주변이4면4, 8이면8을 제안한다. 중간값인데 주변 근거도 없으면 두 후보와 미결 이유를 남긴다.
3. **어떤 간격도 변경하기 전에** 요약을 보여준다. 검사한 고유 요소 수/간격값 수, 미확인 범위, 프레임별 모든 off-grid·검토값의 `현재→제안`, 보존값과 이유를 포함한다. 예: `Card padding: 14 → 16`. 개별 문제를 대표 표본만으로 축약하지 않는다. 의도된 별도 체계만 그룹 단위로 보고한다.
4. 간격 수정이 요청/승인된 범위라면 요약을 보여준 뒤 일반 수정을 진행한다. 읽기 전용·감사만 요청한 작업은 제안까지 전달한다. 의도된 별도 체계의 미승인 전환은 확인을 기다리고 독립적인 허용 작업을 계속한다.
5. 변경하는 것은 간격 속성뿐이다. 구조, 크기/고정 높이, hug/fill, 콘텐츠, 글자·반경·stroke·스타일을 바꾸지 않는다. 숫자를 맞추기 위해 폭이나 내용을 바꿔 강제로 재배치하지 않는다. 간격 변경으로 생긴 자연스러운 위치 이동은 전후를 확인하되, 줄바꿈·잘림·가림·터치 영역 문제가 생기면 무관한 크기/폰트 수정으로 보상하지 말고 해당 간격 적용을 되돌려 미적용 이유를 남긴다.
6. 실제 대상 폭·상태에서 사방 최종 거리, 그룹 리듬, 줄바꿈/넘침, 첫·마지막 내용 접근과 초점을 재검증한다. 숫자·문서만 검사했으면 렌더/행동은 미검증이다. 한 프레임의 결과를 전체 페이지로 확대하지 않는다.

## 기록과 전달

감사 표: `프레임/선택자 | 역할 | 속성/방향 | 단위·출처 | 변수/토큰 | 현재→제안→적용 | 판정 | 근거·검증`.

수정 전 요약과 수정 후 결과를 구별한다. 적용하지 않은 값과 이유, 실제 검증 범위, 남은 문제를 유지한다. 마지막에 관찰된 지배 리듬을 한 줄로 남긴다. 예: “구조는8단위, 촘촘한 내부 간격은4단위 리듬으로 정리했습니다.” 토큰/6단위 그룹이 남았다면 그 범위를 함께 밝히고 전체가8단위라고 주장하지 않는다.

평가 입력과 반례는 [SPACING-AUDIT-01–05](../../../evals/cases.md#spacing-audit-01--같은-역할의-그룹과-중간값), 문서 대조 범위는 [평가 기록](../../../evals/results/spacing-audit.md)에 연결한다.
