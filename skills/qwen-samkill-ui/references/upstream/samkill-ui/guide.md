# Samkill UI

`$samkill-ui`를 단일 진입점으로 사용한다. 요청에 해당하는 아래 스킬을 직접 읽고 실행한다. 사용자에게 스킬을 다시 호출하라고 넘기거나 모든 스킬을 한꺼번에 읽지 않는다. 세부 기준은 각 스킬을 관리 원본으로 유지한다.

## 시작

작업 대상 프로젝트와 요청 범위부터 확인한다. 대상의 `AGENTS.md`, 루트 `DESIGN.md`, 관련 맥락·계약·실패 기록이 있으면 읽는다. 이 스킬이 설치된 저장소를 대상 제품으로 착각하지 않는다. 이미 제공된 요구와 충분한 레퍼런스·분석은 재사용한다.

기본 화면 배경은 `#FFFFFF`로 고정하고 다크모드는 사용자가 명시적으로 요청할 때만 적용한다. 오프화이트·브랜드 틴트·어두운 레퍼런스·시스템 테마를 기본 배경 선택의 대안으로 삼지 않는다. 배색 후보와 종속 스킬 인계에도 이 제약을 전달한다.

필요한 스킬과 이유를 짧게 알리고 작업을 이어간다. 아래 표의 모든 분기에 대해 요청·현재 단계에 해당하는지 판단하고, 해당하는 스킬은 모두 적용한다. 하나의 대표 스킬을 골랐다는 이유로 다른 해당 분기를 생략하지 않는다. 구현 중 문구나 가입 흐름이 생기면 그때 해당 스킬을 추가한다.

## 필요한 스킬의 실행 확인

이 진입점을 읽는 것만으로 연결된 스킬의 본문이 로드되거나 별도 실행되는 것으로 간주하지 않는다. 작업에 필요한 각 `guide.md`를 실제로 읽고, 그 스킬이 현재 단계에서 요구하는 참고 문서도 읽어 적용한다. 표의 요약으로 본문을 대신하지 않는다. 현재 대화에서 이미 읽은 동일 기준은 재사용할 수 있다. 여러 파일을 묶어 읽은 도구 결과가 잘렸으면 누락된 본문을 나눠 다시 읽는다. 파일 이름·첫 부분·검색 발췌만 확인하고 전체 필수 기준을 읽었다고 기록하지 않는다.

시작할 때 요청별 연결 표를 검토해 필요한 스킬과 적용 시점을 정한다. 기존 작업 문서나 짧은 작업 메모에 `스킬 | 필요한 이유/단계 | 실제 읽은 경로 | 적용 결과·증거 | 상태`를 남긴다. 상태는 예정·읽음·적용·검증·접근 불가·해당 없음으로 구별한다. 이름을 언급하거나 본문을 읽은 사실만으로 적용·검증 상태로 올리지 않는다. 유효한 기존 분석을 재사용하면 해당 계약 경로와 현재 요청에 맞는 이유를 연결한다. 읽기 전용이면 이 기록도 채팅에만 둔다.

UI 구현에서는 구현 전에 `reference-to-ui`를 읽고, 원본을 분해하거나 분석의 유효성을 판단할 때 `reference-decompose`, 핵심 화면 비교와 최종 검증 전에 `reference-review`를 읽는다. 필요한 레퍼런스가 부족하면 `uibowl-research`, DESIGN.md 작성·갱신이면 `design-md`, 한국어 제품 문구 작성·수정이면 `ux-copy`, 가입·첫 사용·동의·복구 흐름이면 `onboarding-flow`를 해당 단계에 추가한다. 기존 자료 재사용은 재검색·재작성 생략의 근거이며 필요한 기준의 읽기·적용을 생략하는 근거가 아니다.

UI 구현의 적용 확인은 아래 산출물과 연결한다. 세부 검사·형식은 종속 스킬을 따른다. 작은 수정은 기존 문서나 짧은 메모에 필요한 범위만 남긴다.

| 시점 | 그때까지 필요한 적용 결과 |
|---|---|
| 설계·각색 전 | 사용자 과제와 대상 DESIGN.md 확인. 원본/기존 분석의 확인 상태, 요소·관계 계약. 조사나 DESIGN.md 작성·갱신이 필요하면 해당 스킬의 결과. |
| 구현 전 | reference-to-ui의 배치·결합·구성·토큰·코드 기준을 실제 구현 계약에 연결. 작성할 한국어 문구와 가입/동의/복구 흐름이 있으면 ux-copy와 onboarding-flow의 계약. |
| 핵심 화면 확장 전 | reference-review의 기준으로 원본과 실제 렌더를 비교하고 핵심 퇴보를 수정·재검증. 이미지·토큰 파일·분석 문서의 존재만으로 이 단계 완료를 표시하지 않는다. |
| 최종 전달 전 | 실제 사용처·문구·관련 상태/전이·시각/행동·디자인 게이트 결과와 모든 해당 스킬의 적용 근거 확인. 미실행 검증과 도구 제한의 영향 범위를 유지한다. |

각 단계에서 종속 `guide.md`의 필수 참고 문서도 적용 기록에 포함한다. 예를 들어 구현의 토큰/구성/결합 기준, 한국어 문구의 글쓰기 기준, 리뷰의 디자인 게이트/실패 목록은 상위 스킬 이름만 기록해서 완료하지 않는다. 전체 참고 폴더를 일괄 로드하지 않고 해당 단계의 필수·조건부 요구를 따른다.

새 Primary 선택이나 색 적합성·강조 교정이 있으면 reference-to-ui의 [Primary 컬러 선택](../reference-to-ui/references/primary-color.md)을 구현 계약과 실제 핵심 화면 비교에 포함한다. 기존 브랜드·명시 색은 보존하고 색칩·토큰·대비 검사만으로 선택을 완료했다고 하지 않는다.

간격 설계·교정·리듬 감사가 있으면 [Spacing Audit](../reference-to-ui/references/spacing-audit.md)을 읽고 역할별4/8단위 판단, 변수/토큰 보존, 수정 전 요약과 수정 후 실제 검증을 적용 기록에 포함한다. 읽기 전용은 제안으로 끝내고 의도된 별도 체계의 미승인 일괄 전환은 확인한다. 일반 수정마다 별도 승인을 요구하지 않는다.

작업 중 범위가 바뀌거나 새 화면·상태가 생기면 필요한 스킬을 다시 확인한다. 핵심 화면을 확장하기 전과 최종 전달 전에 예정·읽음에서 멈춘 필수 항목을 확인하고 가능한 적용·검증을 수행한다. 접근 불가는 원인과 영향 범위를 남기며, 필요 없는 스킬은 해당 없음 이유를 남긴다. 검색만·문구만·명세만 요청한 작업에 전체 UI 구현 절차를 추가하지 않는다. 최종 보고는 실제 산출물·검증을 우선하고 적용 누락·접근 실패가 있으면 함께 밝힌다.

## 요청별 연결

| 요청 또는 현재 단계 | 읽고 적용할 스킬 | 범위 |
|---|---|---|
| 레퍼런스 검색·앱 비교·상세 조사 | [uibowl-research](../uibowl-research/guide.md) | 실제 이미지와 출처를 확인한다. 검색만 요청하면 결과 전달에서 끝낸다. |
| 설계·구현용 원본 확보, 요소 분석·재현 실험 | [reference-decompose](../reference-decompose/guide.md) | 각색·구현 전에 요소·관계·조립 계약을 만든다. 유효한 기존 분석은 재사용한다. |
| 쇼핑몰 상세페이지 이미지·긴 세로형 상품 소개 제작 | 설치 스킬 목록의 `pdp-design` | 목록에 제공된 실제 guide.md 경로를 읽고 고객 질문·근거를 기준으로 레퍼런스 분해, HEX 설계, HTML 제작, 이미지 출력·검수를 연결한다. 이 저장소의 형제 스킬로 가정하지 않는다. 크롤러는 별도 프로그램으로 유지한다. |
| UI 설계·구현·리디자인·토큰 수정 | [reference-to-ui](../reference-to-ui/guide.md) | 사용자 과제와 레퍼런스 장점을 연결해 요청한 화면을 만든다. 필요한 조사·분해와 최종 리뷰까지 이어간다. |
| 대상 DESIGN.md 작성·갱신, 구현 전 문서 누락 | [design-md](../design-md/guide.md) | 실제 제품 자료로 기준을 정리한다. 읽기 전용이면 누락·변경안만 보고한다. |
| 한국어 UI 문구 작성·교정 | [ux-copy](../ux-copy/guide.md) | 행동·조건·비용·선택권을 보존한다. 문구만 요청하면 화면 재설계를 추가하지 않는다. |
| 가입·첫 사용·동의·실패 복구 흐름 | [onboarding-flow](../onboarding-flow/guide.md) | 상태·전이·뒤로 가기·재진입을 연결한다. 화면 구현 여부는 사용자 범위를 따른다. |
| 기존 화면 리뷰, 구현 후 검증 | [reference-review](../reference-review/guide.md) | 실제 화면·행동·토큰과 실패 기록을 대조한다. 리뷰만 요청하면 수정하지 않는다. |

## 구현 요청의 진행과 종료

`reference-to-ui`를 중심으로 필요한 분기를 연결해 실제 작업을 완료한다. 레퍼런스가 충분하면 재검색하지 않는다. 새 원본은 `reference-decompose`로 분석한 뒤 적용하며, 핵심 화면을 원본과 먼저 비교한 후 의존 화면으로 확장한다. 한국어 문구는 `ux-copy`, 가입·복구는 `onboarding-flow`를 함께 적용한다.

각 스킬이 요구하는 구성·토큰·코드·시각·행동 검사를 생략하지 않는다. `reference-review`의 디자인 게이트와 실패 목록을 적용하고, 권한 내 중요한 차이를 수정·재검증한다. 빌드 성공을 시각 검증으로 바꾸거나 FAIL/UNVERIFIED를 완료로 표시하지 않는다.

명세만 요청하면 `spec-only`, 읽기 전용이면 분석과 수정안으로 종료한다. 형식 미지정 UI 디자인은 수정·렌더 가능한 화면으로 제공한다. 문구·검색·리뷰 전용 요청에 전체 구현 절차를 강제하지 않는다. 호출 자체로 커밋·푸시·배포·외부 전송 권한을 만들지 않는다.

읽기 전용에서는 리뷰 문서·게이트 보고서·ledger 누적도 대상 파일에 쓰지 않고 결과를 채팅으로 전달한다. 기록을 생성하지 못한 검사와 실제 수행한 판독 범위를 구별한다.

## 연결과 도구가 없을 때

표의 링크는 이 파일의 실제 위치를 기준으로 한 형제 스킬 경로다. 링크를 열 수 없으면 세션의 설치 스킬 목록에서 같은 이름을 찾아 읽는다. 둘 다 없으면 누락된 스킬을 명시하고 접근 가능한 기준과 사용자 자료로 독립 작업을 이어간다. 읽지 못한 기준을 적용했다고 하거나 검증 불가능한 항목을 통과시키지 않는다.

UIbowl 등 도구의 연결·인증 실패는 검색 성공과 구별한다. 제공된 이미지·기존 계약으로 가능한 작업은 계속하고 직접 확인하지 못한 부분을 표시한다. 자동 설치나 인증 변경을 전제로 하지 않는다.

결과는 실제 산출물, 주요 결정, 수행한 검증, 남은 미확인 사항으로 전달한다. 선택한 스킬 목록만 출력하고 끝내지 않는다.
