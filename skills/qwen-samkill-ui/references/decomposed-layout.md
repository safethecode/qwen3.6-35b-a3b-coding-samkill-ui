# Decomposed layout for local models

Read the upstream decomposition guide and its element contract. Record observed reference relationships separately from chosen implementation values and unknowns. Do not infer a font, asset origin or interaction from an uninspected screenshot.

The layout contract supports explicit `modes` alongside widths/states. Declare normal-layout anchors separately from content-preserving enlargement/spacing behavior before repair; keep all requested mode captures in the coverage matrix. Missing captures and unknown observations cannot pass, and adding mode scope does not erase a previously failed observation.

## Before generation

Match the reference and candidate screen purpose and visible state before comparing them. A checkout screenshot does not specify a catalogue hero. For a photo-led reference, obtain and inspect suitable real media with provenance before implementation; abstract decorative shapes are not a substitute for missing product imagery. Record substitutions explicitly. For illustration-led references, preserve that medium instead of imposing photography. Freeze the initial render before changing the contract.

Record each positive reference anchor as `observed region/relationship → intended implementation counterpart → same-width rendered evidence → retained/degraded/unknown`. Include the composition, proportions, density and hierarchy that make the source effective, not only its theme or component names. Distinguish observed image geometry from chosen CSS values; unknown source fonts/DPR remain unknown. An excluded profile, advertisement or social feature does not justify losing the remaining screen's structure or calling concept-only transfer faithful. Keep exact reproduction, product adaptation and functional regression claims separate. If the central composition is degraded, retain a failed reference-synthesis assessment even when exclusions and mechanical checks are valid; repair and inspect the whole composition before extending dependent screens.

Define shared typography, colors, spacing, surfaces and responsive behavior. Divide the screen into semantic elements with explicit owned text, assets, actions and states. Give each element its available width, parent padding, adjacent read-only structure and forbidden duplicate content. Assign inter-element spacing to the assembly so two elements cannot both add it.

Preserve the reference's grouping. Identity, description, price and actions need a deliberate reading order. A favorite that belongs to identity must stay there; price and consultation can share a quiet footer only where the reference and available space support it. Avoid adding separators, large buttons or explanatory paragraphs absent from the contract. At narrow widths, wrap the intended groups rather than shrinking type or forcing every control onto one row. These are reference-specific relationships, not a universal card template.

Use real font files and verify actual rendered families, glyph fallback and weights through the typography checks. Use verified official icon assets and the required selected/unselected states. Asset presence alone does not prove matching size, paint, placement or behavior.

## Bounded implementation

The repository's explicit static pilot is `node scripts/generate-components.mjs TARGET EVIDENCE`, with `design/component-plan.json` and typography prepared first. See the repository's `docs/COMPONENT-GENERATION.md` for its schema. It generates one element at a time and assembles accepted fragments without a model rewrite. Fixed semantic HTML may request CSS only. Record host-supplied markup, shared CSS, fonts and selector scoping as assistance. This CLI is not an automatic OpenCode route and does not implement a complete product workflow by itself.

Render each element in a sample with the same available width and horizontal inset as its assembled slot. Review samples and the full page at desktop and mobile widths. Repair one owned region while retaining correct neighbors; rerun affected checks and the assembled view. The pilot's resume requires unchanged inputs; do not claim changed-plan checkpoints remain valid. Complete all requested interactions separately, including empty, error and recovery states.

When independent generations repeatedly break an already agreed structural relationship, move that relationship into the shared assembly scaffold and supply immutable semantic HTML before requesting local CSS. Keep stable IDs for measured roles rather than assuming a model-chosen class survives the next run. Record which markup and layout declarations the host supplied. This reduces the model's writable responsibility; it does not demonstrate independent design competence. Do not turn a screen-specific action row into a universal preset. Verify enlarged text again: a correct row can still hide its label with nowrap, ellipsis or a fixed height. Use wrapping and content-driven control height where the label must remain complete.

Each CSS unit needs the actual rendered element structure, including JavaScript-created children, exact attribute values, attribute owners and available custom properties. Supply complete CSS statements with nearby inheritance context. A tag-only shell omits dynamically rendered cards; a declaration cut midway omits valid existing source. Keep the writable unit explicit and its dependencies read-only.

Parsed and scoped CSS is a provisional result. Browsers can ignore misspelled declarations, discard values with missing custom properties or override valid rules through the cascade. For an already prescribed role, record its expected computed properties before the repair and inspect the actual visible owner; `computedStyle` layout rules accept canonical computed strings. Check inherited variable definitions and applicable fallbacks rather than assuming every `var()` resolves. Do not infer expected values from the generated output or use these mechanical checks as visual approval. Native controls can compute differently from their declared CSS; verify that behavior before blaming the model or exempting the role.

If a repair changes unrelated rules inside its semantic component, narrow the existing `repairComponent` API boundary itself: pass only the affected complete CSS fragment as `before.css`, with the fixed full element HTML retained as context. The fragment must occur exactly once in the stylesheet. Patch oldString values then match that fragment rather than every rule in the component; an oldString targeting a protected neighbor is rejected before writes. This protects existing neighbor bytes, not all computed effects: a new overriding selector or important declaration can still affect a neighbor. Reject unexpected selector/property changes against the declared scope and verify rendered behavior before accepting the result. Retain the rejected full-component response and verify protected calendar/focus/asset/style bytes after the narrower repair. Do not rely on a read-only sentence while still supplying all neighbor CSS as writable input. This bounds repair responsibility; it does not establish independent design quality.

If the model still edits the read-only parent, remove that parent's full stylesheet from the repair payload: deliver only the inherited declarations/tokens needed by the affected rule as read-only context and keep one uniquely identified writable fragment. Recurring patch-target confusion can be reduced to fixed selector/declaration slots. Validate every supplied declaration, all required properties and the resulting computed values before advancing; a slot schema alone does not prevent omissions or misspellings. Record host-selected selectors and assembly as assistance, preserve the rejected attempts and rerender the complete view with protected neighbors and text stress.

If declaration slots still repeat forbidden properties, narrow again to property-value slots: the host owns the selector/property names and the model supplies only their values. Do not accept an out-of-scope response just because the extra declaration repeats an existing value. Preserve both rejected attempts and the typed assembly. Check actual computed styles and the complete rendered state afterward; constrained output is assisted repair, not independent generation evidence.

Before a markup repair, list every consumer of that owned markup: assembly, dynamic template, standalone sample and component-plan handoff. A shared stylesheet does not synchronize their HTML. Apply the accepted bounded response to all matching consumers or explicitly regenerate the dependent sample from the unchanged assembled element. Compare canonical owned markup before the next generation checkpoint. Record host propagation separately from model generation; an omitted consumer is a host integration defect. Then recapture source-bound browser evidence rather than attaching earlier receipts to the changed plan/sample.

When ownership changes, replace obsolete instructions instead of appending a competing rule. If a title becomes part of a heading/action row, explicitly assign the row-to-calendar gap to the row and the title margin to the title; do not leave the old title margin in the preserved prompt. Reconcile the brief, element prompt, shared CSS, sample and layout contract before the next call. Preserve the contradictory input as a failed historical version, not a valid unchanged checkpoint.

For known typography roles, declare numeric `fontSizePx`, `fontWeight` and unitless `lineHeightRatio` alongside the intended rendered families in `design/typography.json` before generation. The shared font inspector checks these optional expectations against actual visible text owners, including nested labels and placeholders. Family/minimum-size checks cannot approve a22px title that silently became a32px browser default through an unmatched selector. Fixed-DOM selector examples are context, not a guarantee that the model used them. Inspect the actual matched rule and render. Supply `textScale:2` only after real200% enlargement; it scales the expected font size, not weight or line-height ratio. An intentionally imposed spacing override needs its separately recorded expectation rather than silently treating a changed ratio as the original role.

Before assigning those numeric roles, record the reference's relative heading/content emphasis: the two actual owners, observed size/weight relationship, chosen implementation bounds and unknown native CSS/font/DPR. Do not automatically make every task heading larger or heavier than its dominant card content. Where the observation supports a measurable relationship, use `typeRelation` from [the relative typography API](layout-contract-api.md) alongside exact font roles. Give the local element its read-only neighbor role. If the host's existing numeric default contradicts the observed relationship, replace that input before the next request and retain its old version; do not call faithful execution of the wrong prompt a model-only defect. Relative metrics supplement direct comparison and never establish visual parity by themselves.

Related text and icons form a semantic alignment group. Declare whether the reference associates the icon with the first text line, the complete label block or another observed baseline; do not apply one universal center preset to unrelated roles. A trailing chevron opening a complete room label can center on that label block, while an explicitly first-line row action keeps its first-line contract. Compare the actual text owner and official SVG slot/paint, not only the shared flex parent's box. Different text line-height and icon height make `align-items:flex-start` visibly wrong even when both boxes begin at the same y. Verify short and wrapped labels, narrow/wide widths,200% text,spacing stress,focus and actual edge clicks. Keep44px hit targets and official geometry; do not nudge one screenshot with transforms or manual line breaks. Encode the chosen relationship, such as a strict `sameRow` between the label and icon, before local repair and retain the failing capture.

An external SVG loaded through an img element does not inherit its surrounding label's currentColor into its painted document. When state changes the color of a functional monochrome icon, use a color-capable official SVG representation or an explicitly verified asset variant. Preserve official paths, viewBox, geometry and accessible labels; multicolor brand assets are a different case. Inspect actual selected and unselected icon pixels, because the img element's computed color can match its label while the SVG still paints black. The contract API's `monochromePaint` rule checks predeclared icon/plain-text colors on a resolved opaque white surface; its unsupported contexts stay unknown. Keep its state/mode coverage and separate official geometry, control and reference checks.

Reference-sized text and container insets are one layout budget. Record each label/value role and its normal line box, internal gap and all four owned padding values before styling. A compact read-only date summary must not inherit a larger generic body/value role merely because it uses strong text. Preserve the reference's value/label hierarchy with explicit selectors and the project's font-size floor; inspect the resulting inner whitespace at the same display width. Keep a single parent/child padding owner, natural height and complete dates during enlargement. Fix the role/inset contract instead of removing padding to accommodate an oversized default, shrinking unrelated body text or fabricating original CSS values.

For decorative illustrations, implement the frame's dimensions and positioning context first, then each shape variant using the exact rendered attribute value. Review the painted result as well as its box: a positive-size empty background is not a completed illustration, and absolute pseudo-elements can escape a zero-height owner. Test every variant in the assembled page. For forms, verify the actual font and weight of inputs, selects and placeholders separately from body text. A supplied font file alone does not establish control inheritance.

## Behavior units and semantic acceptance

For an interactive application, separate validation/date utilities, state persistence, DOM rendering and event wiring by their actual dependencies. Give a state-only request its API and record schema; unrelated page HTML and CSS make that responsibility harder to identify. Preserve stable IDs when rendering and wiring are separate. This is a decomposition option for work that does not complete reliably, not a requirement to split every small script.

Syntax and export checks cannot approve behavior. Exercise a valid create/change/remove/reload sequence as well as malformed records and failed writes before accepting a state module. For synchronous local storage, derive the next array, persist that candidate and update in-memory records only after the write succeeds. Saving the old array or mutating memory before persistence breaks recovery. Validate actual calendar dates, identifiers and required text rather than accepting strings that only match a regular expression.

When HTML interpolation is forbidden, specify the permitted operations concretely: replaceChildren to clear, createElement/append to construct controls, clone an existing template and assign user text through textContent. An HTML-escaping helper does not satisfy a no-innerHTML contract. Test the resulting interaction rather than accepting an absence-of-keyword check as proof.

If a diagnosed repair repeats the same defect, reduce the writable unit to one function or explicit statement slots. Preserve the raw rejected outputs and accepted neighbors. Verify semantic behavior again: a validation patch can accidentally insert an unconditional return and disable valid creation. Record host-selected boundaries, export/assembly glue and model-generated logic separately. Keep thinking settings, token limits, elapsed time and completed output as experimental evidence; a single successful narrow repair does not establish a better default or general reliability.

At a module boundary, declare parameter types, exact imported names and existing selectors. Probe a generated renderer with real typed state in the browser before passing it to the event-wiring stage. Treating an ISO date string as a Date object or inventing an external helper can propagate a bad interface into every later stage even when each file parses. A change in the accepted interface requires a new caller contract and replay, not a syntax-only checkpoint.

When both raw and parsed forms of one value exist, deliver the typed signature, one actual valid/invalid example and the complete transitional state shape. Distinguish an ISO string from numeric UTC milliseconds; a helper accepting raw strings cannot consume the parsed number just because both represent a date. Include valid empty and partial drafts as well as complete records so a mandatory parse does not reject an allowed transition. Record host-provided invariants separately from generated logic and test the caller against the real dependency before styling it. This is a boundary contract,not permission to invent a new dependency or approve model compliance from an example alone.

For a calendar or another repeated interactive grid, isolate pure value arithmetic, safe rendering, event/lifecycle ownership and styling. Month keys and full dates need different typed examples; validate primitive input types before concatenation and test calendar arithmetic across UTC offsets. A renderer that replaces controls requires explicit restoration of actual focus and the single roving tabstop. Test empty/pending/complete/error drafts,Cancel/Escape/Apply,immediate reopen and route exit against the real caller. Preserve browser modifier shortcuts; intercept only the component's declared key combinations. If bounded generation still fails these invariants,use a separately attributed tested runtime rather than presenting a host repair as unattended model success. This does not require replacing an existing working native control or rebuilding every small component.

During CSS repair,map every diagnosis to the actual selector and owned property before accepting it. A caption cannot own the cancel button's padding/type,and an error container must not be hidden unconditionally to remove an empty gap. Check the visible nonempty error and footer containment,not only default screenshots. For repeated grids,verify label tracks against control tracks and state-independent slot sizes at narrow/enlarged widths. Unsupported color/compositing evidence remains unverified until measured separately or replaced by an explicitly contracted,verified surface;do not drop the check to promote a candidate.

Text fitting inside individual controls does not establish separation from neighboring text. For repeated dates or values,declare a role-specific minimum between actual text ranges and check both row and column neighbors with `textGap` in [the contract API](layout-contract-api.md). The minimum belongs to that product contract,not a universal spacing preset. If a semantic grid cannot fit enlarged values with the declared separation,preserve the font and full values;contract a bounded pan or reflow with shared label tracks and one actual scroll owner per axis. Test the active scroll region's keyboard entry,first/last values,whole month/column context,errors and exit controls on short and resized viewports. A desktop pane,font reduction,wrapped digits or an offscreen action is not a substitute for this adaptation. Real device and assistive-technology behavior remain separate checks.

Verify sticky labels against their owned content: a prior section title must not remain visibly isolated after its readable rows have left the viewport. Reveal the focused section and its weekday/column context without moving a pointer target between focus and click dispatch. A focus handler that scrolls to a title can cancel a real click even when programmatic activation passes. Keep actual pointer selection,error transitions,keyboard focus and resize tests alongside layout measurements;do not approve an orphan title from containment alone.

When a responsive or short-height state changes the actual scroll owner,recheck sticky offsets against that owner's padding and margins. The same `left:0` can preserve a gutter in one owner and erase it in another. Keep the existing gutter token and verify the label's actual position after panning;computed offset or parent containment alone does not prove aligned content.

If a bounded CSS repair still corrupts a known selector,freeze the actual selector and property in the host contract and request only a typed value slot. Validate the returned value before assembling it with a CSS parser;reject extra properties,tokens,important or selector fragments. Preserve the failed full-rule output and disclose the host assembly. A successful value slot proves that constrained edit only,not independent styling or reference discovery.

For source-backed JSON examples, the component runner accepts per-element `dataSources` with `id`, a project-relative `file` and a JSON `pointer`. It delivers the selected actual records and binds both source bytes and delivered values. Missing records fail before inference rather than becoming invented helpers or fields. Bounded behavior callers can use the same `readElementDataContext` API. Its limits, pointer syntax and receipts are in the repository's `docs/COMPONENT-GENERATION.md`; data delivery does not prove correct use of the fields or replace semantic tests.

## Executable layout contract

Create `design/layout-contract.json` with a nonempty `rules` array. Each rule needs a unique `id` and `kind`. Selectors must identify exactly one visible element except `absent`, which requires no matching element. Optional `widths` and `states` restrict applicability and must not hide required coverage.

| Kind | Fields | Measured relationship |
| --- | --- | --- |
| firstLineControls | subject, rows, text, controls, tolerance | For explicitly declared variable-height rows, each owned control stays near the first text line center and inside its row. Relative selectors must resolve once per row; zero visible rows cannot pass. Use numeric line-height and visited filled/long states. |
| readingActionFlow | subject, rows, text, body, action, minimumTextEm, reservedInlineWidth, minimumTarget, minGap, maxBelowGap, tolerance | For declared horizontal LTR rows without CSS transforms/zoom, preserve a chosen text reading width and an owned supporting action. Predeclare the nontext width allowance independently of output geometry; empty body space cannot lower it. Keep the action at the row end and first-line aligned when inline; allow it below its complete body only when inline space is insufficient. Require a contained target and bounded gap. This does not prescribe a universal reading width or replace text-loss checks. |
| contained | subject, container | DOM ownership and rendered containment |
| absent | subject | No duplicated or forbidden content in a region |
| below | subject, reference, minGap | Ordered regions with a minimum vertical gap |
| disjoint | subject, reference | Independent regions do not overlap |
| sameRow | subject, reference, tolerance | Horizontally separated regions have aligned vertical centers; tolerance defaults to 2px, maximum 8px |
| rowLimit | groups, maximum | Maximum semantic groups sharing a horizontal row |
| sampleWidth | subject, sample | Sample HTML and assembly have equal width and inset |

For example, a card contract can contain favorite ownership in identity, absence of body paragraphs in identity, body below identity, nonoverlapping price/action, and a row limit across price/action/favorite. Use the actual selectors and observed relationships of the target, not copied selectors from another service. The sample filename must be a local HTML file.

Both browser evaluation routes emit layout-contract evidence. Missing contracts and uncovered viewport/state scopes remain UNVERIFIED; a failed relation is FAIL. Test 1440, 390 and 320 pixel widths alongside existing long-text, 200% text and spacing checks. Preserve source and harness hashes. A contract added after generation is a diagnostic audit, not evidence of predeclared compliance.

First-line alignment alone cannot approve a supporting action that squeezes the primary title into a narrow column. Decompose the text body, its native selection control and the supporting action separately. If a previously host-chosen all-inline rule conflicts with readable enlarged text, preserve its original results, document the conflict and predeclare a replacement relation before another generation. Keep the native selection control aligned with its text; preserve fonts, official icons, labels, targets and full content. A case-specific minimum reading width may be expressed relative to the actual text font, capped by the row's available width after its owned control/insets. Never copy that numeric threshold to unrelated products or call it a measured reference value. Check ordinary rows as well: moving every supporting action below despite sufficient space can create unnecessary height. Review actual normal/enlarged renders and state coverage; passing this geometry relation does not approve visual quality.

When a chosen reading-width contract uses flex wrapping, an intrinsic `auto` basis can make a long title push its supporting action below even where both could fit. Diagnose the actual basis before repeating the whole component. A preferred basis derived from the chosen reading width plus independently measured nontext space can separate the wrap decision from title length. Include native control margins as well as its box and gap; do not assume a20px checkbox and12px gap occupy only32px. Verify the font that resolves an `em` basis matches the declared text role, and test widths around the actual wrap boundary in normal/enlarged modes. Preserve the failed intrinsic-basis response and use a one-rule repair when that is the diagnosed writable responsibility. This is a conditional implementation technique,not a universal row preset.

For a multi-state layout, collect actual `inspectLayoutContract` receipts with explicit state and text-mode names, then use `aggregateLayoutStates` from `scripts/layout-state-coverage.mjs` with nonempty `widths`, `states` and `modes`. Capture the complete requested matrix as well as every rule's declared state/width scope. A reading-state image cannot approve editing-state controls. The aggregator resolves only its structured pending-state notices after matching captures exist; missing cells, stale contract digests, duplicate results and every reported failure remain blocking. Present empty, null or false scopes are invalid rather than permission to skip inspection. Source and harness must stay unchanged throughout one capture batch; do not combine different repaired versions to fill gaps. Callers must assert the actual DOM state and apply real text enlargement before stamping a mode. Receipt metadata does not authenticate source, activate states or certify visual quality.

First-line control geometry starts at the text content box, including its top border and padding. Keep the text selector specific to the owned first-line content; a wrapper's top edge is not necessarily the first text line. Check both unpadded and padded content in generic gate regressions rather than adjusting a fixture to conceal a false alignment result.

Geometry cannot establish reference-level quality. Inspect font appearance, icon states, density, rhythm, copy and complete responsive composition against the reference directly. Assess every active rule in the 75-rule catalog and all eight guides with evidence. Missing visual, interaction or asset evidence remains unknown even when every layout relation passes.

## Read failure is a distinct state

For persistent products, distinguish absent storage, successfully read empty data, malformed data, denied reads and failed writes. Never turn a failed initial read into permission to seed, create or overwrite the unreadable original. Preserve raw data and submitted input; require a successful reinitialization or an explicitly designed recovery flow before mutation. A normal write failure must still permit the product's existing retry behavior. Keep initialization readiness separate from the current error string.

Assign one renderer to each state-bearing DOM node. Controllers must not overwrite the renderer's empty/error decision afterward. Unknown data is not a confirmed empty result. Test the complete sequence: initial read fails, create is attempted, original disk and input remain, reads become available, explicit reload restores the old record, then create succeeds. Test malformed data separately. Check the displayed recovery instruction as well as the write count: a read guard caught by a write-error catch can preserve data but show the wrong recovery action. Keep the read precondition outside that catch. Use these probes before accepting downstream UI modules; passing isolated store exports or a normal create/reload flow does not cover this transition.

## Resolve text sizing conflicts before generation

A reference measurement describes a default-size state. For buttons, headings and other text-bearing regions, translate the observed height into a minimum height with natural growth unless the product explicitly requires a bounded scroll region. Keep exact dimensions for genuinely fixed visual assets or icon-only targets when appropriate. Do not pass a fixed text height to the local model while also requiring enlarged text to remain visible. Resolve that contradiction in the component plan before generation and record the plan change; do not silently weaken the text-stress requirement.

Use unitless line-height for wrapping text so200% font enlargement does not leave the original pixel line-height behind. A text action needs normal wrapping, sufficient padding and automatic height. Preserve complete labels, type size and the ownership of adjacent actions. Inspect actual button text bounds as well as ancestor clipping: native controls can lose label content even with overflow:visible. Missing reused-component samples must be rebuilt from the unchanged assembled content and checked alongside newly split units.
For Korean purpose headings and short labels, inspect200% wrapping at the actual available width. Keep a word such as 목요일 or 추가 together when it fits on a new line; appropriate keep-all plus emergency wrapping can preserve words without shrinking text or adding nowrap. This is a language/content decision, not a blanket ban on wrapping URLs, code identifiers or long unspaced user content. Verify the heading and its neighboring action after the change.

# Preserve screen purpose before splitting components

Check allocated width as well as wrapping. For a declared icon-plus-primary-action row, the primary control must occupy its remaining track; min-width:0 permits shrinkage but width:0 can collapse a grid item into one-character lines. Declare a fillRemainder relation for this two-control pattern and compare actual widths at normal and enlarged text. No clipping and a shared row do not prove readable control geometry. This applies to a flexible primary track, not intentionally compact icon-only controls.

Lock platform scope first. For a mobile-only task, preserve a bounded mobile preview and the observed vertical stack even inside a desktop browser window. Record the chosen preview width separately from measured reference pixels. Do not introduce desktop columns, enlarged desktop headings or alternate navigation without user authorization or an actual reference for that platform. This restriction applies to host-written shared CSS and assembly, not just model-generated components. Remove contradictory desktop instructions from every component prompt. Add maxWidth and below rules without mobile-only width filters so a 1440px test rejects an invented desktop layout. Wide-viewport testing checks the same mobile screen; it does not authorize a new desktop design.

Before a local model styles individual elements, inspect the reference with the upstream reference-decompose guide and record these relationships in DESIGN.md and design/layout-contract.json. Splitting into image, title and button is insufficient.

1. Identify the screen purpose and entry/exit route. A detail screen needs an accessible working return path, including direct entry. Do not invent a branded header to fill the top edge. Describe the observed navigation position and assign its implementation owner. Test the destination, not only the arrow's existence.
2. Describe the canvas and semantic surfaces: which content shares a background, which groups are separated by empty space, and which controls have their own bounded surface. Record observation separately from chosen CSS values. For a reference using white sections on a gray canvas, preserve that grouping without substituting hr elements or thin border dividers. This is reference-specific; do not force cards onto references that use open whitespace.
3. Assign one primary message per state. In a success dialog, completion is primary; product and reservation data are supporting summary content. Hide the previous form's duplicate product summary and title when switching states. A typography difference alone does not prove semantic hierarchy: inspect the complete state screenshot and content ownership.
4. Separate supporting actions from primary actions. When observed or requested, favorite is a quiet bounded control surface, while booking remains the dominant action. Never pack price, favorite and primary action into a single undifferentiated row.
5. Write one compact relation brief per component: parent, siblings, screen purpose, owned content, surface, navigation/state dependencies, observed evidence, chosen values, unknowns and verification. Shared assembly owns relationships crossing component boundaries. Include this brief in each component prompt and pass the machine-readable layout contract during generation.

Use declared `returnNavigation`, `surface`, `typeHierarchy`, `contained`, `below`, `rowLimit` and `absent` rules for measurable relations. Scope rules by states and widths. Run state-specific rules in the actual form/success state; skipped states are unverified, never approved. A static destination attribute does not prove navigation; click it and verify the real destination loads. Surface checks do not establish reference fidelity, and unknown reference CSS must remain unknown. Retain same-width reference/output captures and manually review hierarchy, spacing, icons and typography.

For a declared whole date, short label or numeric unit, `readableToken` inspects actual text ranges and intrinsic width against its semantic owner. Use `token:"whole"` or `token:"number"` with an optional literal `suffix`, plus concrete `subject` and `container` selectors. Preserve a separate normal-layout relation such as `sameRow`: repairing fragmented dates by stacking ordinary-width date cells can still regress the reference. Enlarged/spacing states may need measured reflow; do not shrink or remove text. An intrinsically wider token remains unverified, never an automatic pass. See [the contract API](layout-contract-api.md) for uniform-text scope and unsupported cases. These mechanical checks do not establish semantic date/amount integrity, reference fidelity or independent skill compliance.

Trace the same fact through every actual consumer, including list cards, detail summaries and confirmation dialogs. A whole date in the form does not protect the same date concatenated into a dialog sentence. Declare the separate text owners and check each consumer at normal and enlarged sizes. Keep input, applied summary and saved detail font coverage consistent through the real cascade. Mixed user text can contain emoji sequences or presentation selectors absent from the primary font; verify actual rendered glyph fonts, required licenses and loading/failure states instead of deleting valid input or disabling fallback checks. A platform fallback is acceptable only when the project's declared font policy allows that specific scope.

For saved-entity flows, bind transient outcomes to the affected identity and current status. Test A's completion followed by navigation to B, completed-form reuse after same-tab and actual other-tab cancellation, and a fresh read failure before any reuse shortcut. Cached existence alone does not establish a current successful record. Preserve the input and operation identity through unknown results until explicit reconciliation. Normal return navigation needs the originating item and keyboard context as well as a working route.

Apply text enlargement before opening a dialog too. With the longest valid target name, first focus must not scroll the question and identity start away. After disabling a submitting control, test failure and re-enabling without helper scrolling: complete error guidance and the actual recovery controls must remain reachable, with a stable meaningful focus. A screenshot helper that scrolls actions into view proves only that they can be captured; it does not prove the application recovers focus or exposes the error after an actual failed action.

When user feedback contradicts a decomposition, preserve the previous output and add a correction record: missing observed relationship, affected element/assembly owner, revised input, measurable check and before/after screenshot. Clearly distinguish host-authored correction from independent local model improvement.

For exact typography captures, use `inspectFontRendering` with the predeclared roles. Set `textScale:2` only inside actual 200% text activation. The separate spacing test overrides line height to1.5: pass `lineHeightRatioOverride:1.5` only while that real override is active, retain the original declared role and include returned `metricContext` in the receipt. Restore and recheck the authored ratio afterward. Do not pass a stress override to approve an ordinary screen or infer role fidelity when exact metrics are absent.
